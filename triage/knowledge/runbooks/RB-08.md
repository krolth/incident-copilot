id: RB-08
title: Escalate with insufficient evidence
category: insufficient_evidence
---
## When to use
The evidence cannot support a single conclusion: telemetry is missing for the important window, the signals point
to two or more causes equally, or the anomaly cleared before anyone looked. Saying "not established" is the correct
output here, not a failure.

## Signals
- A gap in logs or metrics covering the onset. Missing data shows as *no data*, not zeros: the log agent or the
  metrics scraper stalled. Check whether the gap covers the first bad minutes.
- Two candidate causes start in the same minute (for example a config push and an unhealthy node), and nothing in
  the available data separates them.
- The alert has already cleared, leaving a few unexplained errors and no trend.

## Steps
1. State plainly that the cause is not established; do not guess.
2. List what was checked, what was missing (which source, which window), and which explanations remain, with the
   evidence for each.
3. If the impact is ongoing, apply only mitigations that are safe under every remaining explanation (for example
   cordon the suspect node *and* hold further config pushes), and page the owning team.
4. If the alert cleared, set a watch on the affected metric and open a follow-up; record the telemetry gap as its own
   ticket.

## Do not
- Pick the most recent deploy or config push as the cause just because it is the only visible change.
- Restart things to "see if it helps": it destroys the evidence and, on game servers, players' games.
