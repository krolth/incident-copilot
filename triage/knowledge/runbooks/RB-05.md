---
id: RB-05
title: Drain and replace a failed node
category: infra_failure
---
## When to use
One host or instance in a pool is failing while the others are healthy.

## Signals
- Errors concentrate on a single host name in the logs; the rest of the fleet is normal.
- Hardware or kernel messages (disk I/O errors, filesystem remounted read-only, NIC resets) on that host.
- Load balancer health checks flapping for one target, giving partial failures (roughly one request in N fails).
- Metrics for the service as a whole look only mildly degraded.

## Steps
1. Identify the failing host from per-host error counts.
2. Drain it from the load balancer so it receives no new traffic.
3. Replace or reimage the node; verify it joins healthy.
4. Confirm the error rate returns to baseline and open a hardware ticket if needed.

## Do not
Roll back software or restart the whole fleet when only one host is affected.
